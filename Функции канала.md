Следующая функция — init_random_generator()
Начнём с инициализации генератора псевдослучайных чисел.

Для чего он нужен?

В нашей экспериментальной части мы будем моделировать двоичный симметричный канал (BSC). Каждый передаваемый бит с определённой вероятностью будет инвертироваться.

Например, если вероятность ошибки равна:
\[
p=0.01
\]

то каждый бит должен иметь вероятность 1% быть инвертированным.

Чтобы моделировать такие события, нам понадобится генератор псевдослучайных чисел.
Шаг 1. Какие библиотеки использовать
В Experiments.c подключим:
#include <stdlib.h>


Эта библиотека содержит функции:
- rand() — получение псевдослучайного числа;
- srand() — инициализация генератора.
Нам понадобится именно srand().
Шаг 2. Что такое seed
У генератора псевдослучайных чисел есть начальное значение — seed (зерно).

Представим:
srand(12345);


После такой инициализации последовательность чисел, получаемая через rand(), будет воспроизводиться при каждом запуске с тем же seed и при одинаковой последовательности вызовов.

Это очень полезно для курсового проекта: мы сможем повторять эксперимент и получать воспроизводимые результаты.

Но если всегда использовать одинаковое начальное значение, последовательность ошибок при каждом запуске будет одинаковой.

Поэтому предлагаю передавать seed в функцию отдельным параметром.
Шаг 3. Объявление функции
В Experiments.h добавь:
void init_random_generator(unsigned int seed);


Почему функция ничего не возвращает?

Потому что её задача — настроить генератор, а не получить случайное число.

Почему мы передаём unsigned int seed?

Чтобы при вызове функции самостоятельно выбирать начальное значение. Например, для воспроизводимого эксперимента можно использовать фиксированное число, а для обычного запуска — значение текущего времени.
Шаг 4. Что должна делать функция
Внутри функции нам понадобится всего одна операция:
srand(seed);


Она устанавливает начальное состояние генератора.

В дальнейшем, когда будем моделировать канал, функция apply_bsc_channel() сможет многократно обращаться к rand().

Важное правило: инициализировать генератор нужно один раз перед запуском серии экспериментов, а не перед обработкой каждого отдельного бита. Иначе мы будем постоянно сбрасывать последовательность случайных чисел.

Следующая функция — apply_bsc_channel()
Теперь приступаем к моделированию двоичного симметричного канала (BSC — Binary Symmetric Channel).

Это первая функция, в которой мы непосредственно будем создавать случайные ошибки в передаваемом кодовом слове.
1. Как работает BSC
Представим, что мы передаём через канал 31-битное слово:
Передаваемое слово:
1011010011010010110100101101001


Каждый бит независимо от остальных может измениться с вероятностью \(p\).

Например, при:
\[
p=0.01
\]

вероятность инверсии каждого отдельного бита составляет 1%.

Возможны два события:
Переданный бит	Результат	Вероятность
0	0	\(1-p\)
0	1	\(p\)
1	1	\(1-p\)
1	0	\(p\)

Именно поэтому канал называется симметричным: вероятность инверсии не зависит от того, передавали мы ноль или единицу.
2. Какую функцию будем реализовывать
Предлагаю следующую сигнатуру:
int apply_bsc_channel(
    uint32_t codeword,
    double p,
    uint32_t *received_word
);


Разберём параметры.
Параметр	Назначение
codeword	Исходное 31-битное кодовое слово
p	Вероятность инверсии одного бита
received_word	Указатель, куда запишем результат передачи

Почему возвращаем int, а не uint32_t?

Чтобы функция могла сообщить об ошибочных входных параметрах.

Договоримся:
- 0 — передача смоделирована успешно;
- -1 — некорректные входные данные.
Само принятое слово будем сохранять через указатель received_word.
3. Алгоритм реализации
Шаг 1. Проверка входных данных
Нам нужно проверить три условия.

Первое — корректность указателя:
if (received_word == NULL)
{
    return -1;
}


Для использования NULL подключи <stddef.h>, если он ещё не подключён.

Второе — корректность кодового слова.

Мы уже использовали аналогичную проверку:
if ((codeword >> CODE_BITS) != 0u)
{
    return -1;
}


Третье — допустимость вероятности.

Вероятность должна находиться в пределах:
\[
0\leq p\leq1
\]

Условие в C можно записать так:
if (!(p >= 0.0 && p <= 1.0))
{
    return -1;
}


Такая запись также отсекает значение NaN.
Шаг 2. Создание копии передаваемого слова
Нам не нужно изменять исходное кодовое слово.

Поэтому создадим локальную переменную:
uint32_t result = codeword;


Теперь result будет содержать копию, в которой мы будем инвертировать биты.
Шаг 3. Перебор всех 31 битов
Создаём цикл:
for (unsigned int bit_index = 0;
     bit_index < CODE_BITS;
     bit_index++)
{

}


Здесь bit_index — индекс бита в представлении C, от 0 до 30.

Для каждой позиции будем генерировать отдельное случайное число.
Шаг 4. Генерация случайного значения
Здесь нам понадобится rand().

Но есть нюанс: функция rand() возвращает целое число в диапазоне от 0 до RAND_MAX.

Чтобы получить число с плавающей точкой в диапазоне от 0 включительно до 1 не включительно, используем:
double random_value =
    (double)rand() / ((double)RAND_MAX + 1.0);


Например, результат может выглядеть так:
0.000314
0.527481
0.891273
0.012345


Каждый новый вызов rand() позволяет получить очередное значение псевдослучайной последовательности.

Почему мы не используем просто rand() % 100?

Потому что нам нужна вероятность, которая может принимать не только целые значения процентов, но и, например, 0.0025, 0.015 или 0.037.
Шаг 5. Сравнение случайного числа с вероятностью p
Предположим, что:
\[
p=0.01
\]

И мы получили:
\[
random\_value=0.004
\]

Поскольку:
\[
0.004<0.01
\]

бит необходимо инвертировать.

Если же получили:
\[
random\_value=0.45
\]

то:
\[
0.45>0.01
\]

Инверсия не выполняется.

Условие будет выглядеть следующим образом:
if (random_value < p)
{
    // Инвертируем соответствующий бит
}


Шаг 6. Инверсия бита
Здесь мы снова используем уже готовую функцию:
toggle_bit()


Не нужно повторно писать побитовые операции XOR.

Внутри условия тебе предстоит обновить переменную result результатом вызова toggle_bit().

Напомню, что индексом для этой функции будет bit_index.
Шаг 7. Сохранение результата
После завершения цикла все 31 позиции будут обработаны.

Остаётся записать результат в выходной параметр:
*received_word = result;


И вернуть успешный статус:
return 0;



4. Общая схема работы
Исходное кодовое слово
31 бит

Для каждого бита:
1. Получаем случайное число от 0 до 1.
2. Сравниваем его с вероятностью \(p\).
3. Если число меньше \(p\), инвертируем бит.
4. Переходим к следующему биту.

Результат передачи
31 бит
Принятое кодовое слово может отличаться от исходного в нескольких позициях.

Следующая функция — generate_error_pattern()
Теперь перейдём к следующей функции экспериментального блока.

Она будет использоваться в нашем дополнительном эксперименте, где мы исследуем корректирующую способность кода Хэмминга при точно заданном количестве ошибок.

Напомню, в плане экспериментов у нас предусмотрены значения:
\[
w=0,1,2,\ldots,31
\]

где \(w\) — количество инвертированных битов.
2.1. Зачем нужна отдельная функция?
Здесь важно различать две модели.

Первая — BSC, которую мы только что реализовали.
apply_bsc_channel(codeword, p, &received_word);


Каждый бит независимо инвертируется с вероятностью \(p\).

Мы заранее не знаем, сколько ошибок окажется в итоговом слове.

Например, при \(p=0.1\) в одном испытании могут произойти две ошибки, в другом — четыре, а в третьем — вообще ни одной.

Вторая — эксперимент с точным количеством ошибок.

Здесь мы заранее задаём количество инверсий.

Например:
\[
w=3
\]

Это означает, что в результате работы функции маска должна содержать ровно три единицы.

Позиции этих единиц выбираются случайным образом.

Именно такую функцию сейчас будем создавать.
3. Что такое маска ошибок
Представим, что у нас есть 31-битное кодовое слово:
Исходное слово:
1011010011010010110100101101001


Допустим, мы хотим создать маску с тремя ошибками.

Получаем:
Маска ошибок:
0000000000100000000000000000101


В маске три единицы. Каждая единица обозначает позицию, в которой необходимо инвертировать бит исходного слова.

Позже мы применим маску с помощью XOR:
\[
\boxed{r=c\oplus e}
\]

где:
- \(c\) — исходное кодовое слово;
- \(e\) — маска ошибок;
- \(r\) — принятое слово.
Например:
Исходное слово:  101101
Маска ошибок:    001010
                 ------
Результат XOR:   100111


Инвертировались ровно две позиции.
4. Объявление функции
Предлагаю следующую сигнатуру:
int generate_error_pattern(
    unsigned int weight,
    uint32_t *error_pattern
);


Разберём параметры.
Параметр	Назначение
weight	Точное количество ошибок, которое необходимо создать
error_pattern	Указатель на переменную для записи сформированной маски

Возвращаемые значения:
Значение	Результат
0	Маска успешно сформирована
-1	Некорректные входные параметры

Добавь этот прототип в Experiments.h.
5. Алгоритм создания маски ошибок
Теперь самое интересное. Нам нужно случайным образом выбрать weight различных позиций среди 31 возможной.

Я предлагаю использовать уже знакомые функции:
- rand() — случайный выбор позиции;
- get_bit() — проверка, установлена ли единица в выбранной позиции;
- set_bit() — установка единицы в маске.
Шаг 1. Проверка входных параметров
Нам необходимо проверить два условия.

Первое — указатель не должен быть нулевым:
if (error_pattern == NULL)
{
    return -1;
}


Второе — количество ошибок не должно превышать длину кодового слова:
\[
0\leq weight\leq31
\]

В C:
if (weight > CODE_BITS)
{
    return -1;
}


Почему не проверяем weight < 0?

Потому что weight имеет тип unsigned int, а значит, отрицательных значений он не принимает.
Шаг 2. Создание пустой маски
Создадим переменную:
uint32_t pattern = 0u;


Почему ноль?

Потому что в начале ни одна позиция не должна содержать ошибку.

В двоичном представлении все 31 бита будут равны нулю.
Шаг 3. Счётчик созданных ошибок
Нам понадобится ещё одна переменная:
unsigned int generated_errors = 0u;


Она будет отслеживать количество уже установленных единиц.

Например:
Текущий этап	generated_errors
Начало	0
Установили первую единицу	1
Установили вторую единицу	2
Установили третью единицу	3

Когда количество установленных единиц достигнет weight, закончим работу.
Шаг 4. Случайный выбор позиции
Теперь нам понадобится цикл:
while (generated_errors < weight)
{

}


Почему здесь while, а не for?

Потому что количество попыток может быть больше количества необходимых ошибок.

Представим, что мы хотим создать маску с тремя единицами.

Случайно выбираем позиции:
Попытка 1: позиция 5
Попытка 2: позиция 5
Попытка 3: позиция 12
Попытка 4: позиция 5
Попытка 5: позиция 20


В итоге мы получили три различные позиции:
\[
5,\ 12,\ 20
\]

Дублирующиеся позиции не должны считаться новыми ошибками.

Для выбора позиции нам нужно получить число от 0 до 30.

Можно было бы воспользоваться выражением:
rand() % CODE_BITS


Но здесь есть небольшой математический нюанс: операция остатка от деления может давать неравномерное распределение, если число возможных значений rand() не делится на 31 без остатка.

Для наших экспериментов лучше сразу избежать этого смещения.

Используем отбраковку случайных значений:
const uint64_t random_range =
    (uint64_t)RAND_MAX + 1u;

const uint64_t usable_range =
    random_range - (random_range % CODE_BITS);


Здесь:
- random_range — количество возможных результатов rand();
- usable_range — наибольший диапазон, кратный 31.
Затем внутри цикла получим случайное значение:
uint64_t random_number;

do
{
    random_number = (uint64_t)rand();

} while (random_number >= usable_range);


Что мы сделали?

Отбросили числа из конца диапазона, которые нарушали бы равномерность распределения после деления на 31.

Теперь позицию можно получить так:
unsigned int position =
    (unsigned int)(random_number % CODE_BITS);


Получаем индекс от 0 до 30.

Это немного более подробный способ, чем rand() % 31, зато он устраняет дополнительное смещение, возникающее из-за операции остатка.
Шаг 5. Проверка выбранной позиции
Теперь необходимо проверить, не была ли эта позиция выбрана ранее.

Используем:
if (get_bit(pattern, position) == 0)
{

}


Почему?

Представим, что в нашей маске уже установлены единицы на позициях 5 и 12.

Если генератор снова выбрал позицию 5, мы должны проигнорировать эту попытку.

В противном случае количество различных ошибок увеличится неправильно.
Шаг 6. Установка бита и увеличение счётчика
Если позиция ещё свободна, устанавливаем единицу:
pattern = set_bit(pattern, position);


Затем увеличиваем счётчик:
generated_errors++;


Обрати внимание: обе операции должны находиться внутри условия if.

Иначе повторный выбор уже установленной позиции будет увеличивать счётчик без создания новой ошибки.
Шаг 7. Сохранение маски
Когда цикл закончится, у нас будет маска с необходимым количеством единиц.

Остаётся записать её через выходной указатель:
*error_pattern = pattern;


И вернуть:
return 0;
